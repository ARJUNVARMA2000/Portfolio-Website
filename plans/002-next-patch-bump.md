## Why this matters

`package.json` pins `"next": "14.2.5"` (exact, no caret). `npm audit` on
2026-06-12 reported this version affected by a long list of advisories
including **critical** (cache poisoning GHSA-gp8f-8m3g-qvj9) and high ones in
the image optimizer (DoS GHSA-g77x-44xx-532m, content injection
GHSA-xv57-4mr9-wg8v, cache-key confusion GHSA-g5qg-72qw-gw5v). This site uses
`next/image` (the hero portrait in `components/home/hero.tsx:176-185`), so
image-optimizer advisories are reachable in production. npm audit states the
fix is available at `next@14.2.35` — the same minor line, so this is a patch
upgrade, not a framework migration. Next 15 is explicitly NOT this plan.

## Steps

### Step 1: Bump the two packages

Run: `npm install next@14.2.35 eslint-config-next@14.2.35 --save-exact`

If 14.2.35 is no longer the newest 14.2.x, prefer the newest 14.2.x patch —
but NEVER a 15.x. Check with `npm view next versions --json` if unsure.

**Verify**: `Select-String -Path package.json -Pattern "\"next\":"` shows
`14.2.35` (or the newer 14.2.x you chose); same check for `eslint-config-next`.

### Step 2: Full local verification

Run in order: `npx tsc --noEmit` → `npm run lint` → `npm run build`.

**Verify**: all three exit 0; build output lists the home page and the four
`/work/[slug]` static pages with no new warnings about deprecated config.

### Step 3: Behavioral smoke test

`npm run dev`, then in a browser (or with curl):

1. `/` renders (hero with portrait image loads — exercises the image optimizer).
2. Any `/work/<slug>` page renders.
3. `/field-notes` redirects to `/` (308) — confirms `redirects()` still applies:
   `curl.exe -s -o NUL -w "%{http_code}" http://localhost:3000/field-notes` → `308`.
4. Open the chat (Ctrl+K) — panel opens; if an API key is configured, a
   question gets a streamed answer.

**Verify**: all four observations as expected.

### Step 4: Confirm the advisory is cleared

Run `npm audit --omit=dev`.

**Verify**: no `next` entry at CRITICAL severity. (Moderate advisories rooted
in the `ai@3` dependency chain will remain — they are tracked as a separate,
deliberately deferred finding; do not fix them here.)
